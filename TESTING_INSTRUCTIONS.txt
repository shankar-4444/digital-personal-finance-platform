DIGITAL PERSONAL FINANCE PLATFORM: TESTING INSTRUCTIONS

IMPORTANT
Run Google Tests only from the isolated build/gtest-data directory. The test fixture creates and removes transactions.dat, savings.dat, budgets.dat, and activity.log in its current working directory. The Makefile runs tests from the isolated directory so real records are not overwritten. Valgrind also runs from build/valgrind-data.

INSTALL REQUIRED TOOLS (Ubuntu/WSL)
    sudo apt update
    sudo apt install build-essential valgrind cppcheck libgtest-dev

MAKE TARGETS
    make             Build the application.
    make test        Build and run Google Tests in isolated data.
    make valgrind    Run the startup/load/exit smoke test under Valgrind.
    make cppcheck    Run general Cppcheck analysis.
    make misra       Run the Cppcheck MISRA addon if available in the installed package.
    make check       Run all targets above.
    make clean       Remove generated executable, test executable, and object files.

The Valgrind target exercises startup, file loading, and normal exit by selecting menu option 11. It does not cover every interactive path. The Google Test suite covers individual functions and persistence behavior but is not a formal coverage certification.

MISRA C
The MISRA target uses the Cppcheck MISRA addon. The available rule coverage depends on the Cppcheck version and addon installation. This check does not establish full MISRA C compliance. Review and document findings and deviations. A plain text file listing rules is documentation only; it does not perform automated verification.

TIMESTAMP TESTING
New transactions receive a timestamp. Updating a transaction refreshes its timestamp. Add/update/delete operations append an event to activity.log. Legacy transaction records have no historical timestamp, so the loader assigns the label Unknown rather than inventing a date.
